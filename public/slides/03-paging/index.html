1. 왜 가상 메모리(Virtual Memory)가 필요할까?

프로그램마다 독립된 주소 공간을 제공하여 서로의 물리 RAM을 침범하지 못하게 격리하는 원리

[가상 메모리의 독립 격리 메커니즘]
프로세스 A
VA: 0x1000
"값 42 쓰기"
CPU MMU
주소 자동 변환
⚡
프로세스 B
VA: 0x1000
"값 99 쓰기"
⬇️ 각자 다른 물리 방으로 분리 매핑
물리 RAM 프레임 12
A의 데이터 (42)
물리 RAM 프레임 48
B의 데이터 (99)
💡 호텔 객실과 가상 주소 비유
모든 손님(프로그램)은 각자 호텔의 "101호" 키를 받고 들어간다고 생각합니다.
하지만 프런트 데스크(MMU)는 손님 A는 신관 101호로, 손님 B는 본관 101호로 안내하므로 둘은 결코 마주치거나 짐을 덮어쓸 일이 없습니다!
📌 핵심 포인트
  • 가상 주소(VA): 프로그램과 개발자가 다루는 주소. 모든 프로그램은 0번지부터 혼자 메모리를 독점한다고 여깁니다.
  • 물리 주소(PA): 실제 RAM 칩의 물리적 핀 번호.
  • MMU: CPU 내부에서 매 메모리 접근마다 VA를 PA로 실시간 변환해주는 초고속 하드웨어.

2. 4KB 단위의 비밀: 페이지(Page)와 프레임(Frame)

바이트 단위로 기록하면 장부가 8배 커진다! 4,096바이트 덩어리로 관리하는 이유

[가상 페이지 ➔ 물리 프레임 1:1 매핑]
페이지 0 (4KB)
페이지 1 (4KB)
페이지 2 (4KB)
➔
➔
➔
프레임 88 (RAM)
프레임 12 (RAM)
프레임 45 (RAM)
💡 가상에서는 이웃한 페이지(0, 1, 2)라도 실제 RAM에서는 흩어져 저장될 수 있습니다!
📖 도서관 원고지와 보관함 비유
글자(1바이트) 하나마다 도서관 보관함 위치를 적어두면, 장부 종이값(8B)이 책 본문보다 8배 더 듭니다!
따라서 도서관은 4,096자(4KB)씩 원고지 묶음 단위로 보관함에 넣습니다.
📌 용어 완벽 정리
  • 페이지 (Page): 가상 메모리를 4KB씩 자른 한 칸.
  • 프레임 (Frame): 실제 물리 RAM을 4KB씩 자른 한 칸.
  • 페이지 테이블 (Page Table): "몇 번 페이지가 몇 번 프레임에 있는가?"를 적어둔 OS의 장부.

3. 주소의 비밀: 오프셋(Offset)은 왜 그대로 남을까?

4KB = 2¹² = 4096바이트! 하위 12비트는 변환 없이 100% 그대로 통과하는 원리

[가상 주소 ➔ 물리 주소 비트 결합 원리]
상위 36비트 (건물 번호) VPN: 0x40403
하위 12비트 (방 번호) + 0xA2C
⬇️ 페이지 테이블 변환 ⬇️ 변환 없이 직통 통과!
물리 프레임 번호 PFN: 0x82F1
오프셋 그대로 결합 0xA2C
최종 물리 주소: 0x082F_1A2C
🏢 아파트 단지와 호수 비유
"은마아파트 302호"가 재개발되어 "래미안 302호"로 이사했다고 해봅시다.
아파트 이름(건물 번호)은 완전히 바뀌었지만, 문 앞의 302호(방 번호)는 바뀔 필요가 없습니다!
📌 왜 정확히 12비트일까?
212 = 4,096입니다. 4KB 페이지 안에서 0번째 바이트부터 4,095번째 바이트 중 "몇 번째 글자인가?"를 가리키는 데 정확히 12비트(16진수 3자리)가 필요합니다.
따라서 하위 12비트(오프셋)는 계산할 필요 없이 그대로 내려옵니다.

4. 속도의 비결: TLB와 하드웨어 워커(Walk)

두꺼운 장부를 매번 4번 뒤지는 대신, 1사이클 만에 즉시 찾아내는 CPU 내부의 단축 다이얼 캐시

[TLB 캐시 조회와 Table Walk 경로]
가상 주소 요청 (VA: 0x4040_3A2C)
⬇️
1. CPU 내부 TLB 캐시 확인
⚡ Hit 시 약 0.25ns (1 사이클 만에 완료!)
✓ [TLB Hit] ➔ 즉시 PA 변환 ✕ [TLB Miss] ➔ 아래로
2. 4단계 Table Walk (L0 ➔ L1 ➔ L2 ➔ L3)
RAM 메모리를 4번 순차 접근 (약 240ns 소요)
📞 단축 다이얼과 두꺼운 전화번호부 비유
자주 통화하는 친구 번호는 단축 다이얼 1번(TLB)을 눌러 1초 만에 연결합니다.
단축 다이얼에 없을 때만 두꺼운 전화번호부(페이지 테이블)를 뒤적여 찾아보고, 찾은 번호는 단축 다이얼에 등록(Fill)해 둡니다.
📌 국소성(Locality)의 축복
컴퓨터 프로그램은 한 번 접근한 페이지 근처를 계속해서 반복 접근합니다.
따라서 첫 1회만 Miss가 나서 워크를 돌 뿐, 실제 실행 중인 명령어의 99% 이상은 TLB Hit로 초고속 처리됩니다.

5. 페이지 폴트(Page Fault)와 세그폴트(Segfault)

폴트는 고장이 아니라 OS에 작업을 요청하는 신호이며, 진짜 잘못된 접근만 SIGSEGV로 종료된다

[Valid=0 발생 시 3대 분기 흐름]
장부에 연결 없음 (Valid=0) ➔ Data Abort 동기 예외 발생
1. 지연 할당 (Minor Fault)
malloc 후 처음 만진 영역 ➔ OS가 0으로 채운 새 프레임 연결 ➔ 명령어 재실행(성공)
2. 스왑 인 (Major Fault)
SSD 스왑 영역으로 쫓겨났던 페이지 ➔ RAM으로 복원 ➔ 명령어 재실행(성공)
3. 무단 침범 / 잘못된 주소 (Crash)
nullptr 역참조(0번지) or 읽기 전용 변조 ➔ OS가 SIGSEGV 전달하여 강제 종료
🎫 도서관 대출증과 호출 벨 비유
서가에 책이 꽂혀 있지 않다고(Valid=0) 불이 난 것이 아닙니다!
사서(OS 커널) 호출 벨을 누르면, 사서가 지하 보관고(SSD)에서 책을 가져와 서가에 꽂아주고 손님은 다시 원래 하려던 독서를 계속(Re-execution)합니다.
📌 Segmentation Fault의 본질
nullptr(0번 주소)는 OS가 의도적으로 아무 물리 방도 연결해 두지 않은 '금지 구역'입니다.
하드웨어가 비정상 접근을 즉시 감지하여 다른 프로그램의 메모리를 망가뜨리기 전에 안전하게 멈추는 것이 세그폴트의 진짜 역할입니다.
