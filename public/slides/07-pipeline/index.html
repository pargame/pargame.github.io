1. 단일 사이클 CPU의 치명적 한계
단일 사이클 프로세서는 가장 실행 시간이 긴 명령어(예: 메모리 로드 LDR = 1,000ps)에 맞춰 클럭 주기를 설정해야 합니다.
결과적으로 400ps면 충분한 단순 ADD 연산도 1,000ps 동안 기다려야 하므로, 클럭 주파수를 1GHz 이상으로 끌어올릴 수 없는 구조적 병목이 발생합니다.
2. 5단계 분할과 클럭 주기 단축
명령어 실행 경로를 200ps 단위의 5개 독립 하드웨어 스테이지로 물리 분할하면, 클럭 주기를 1,000ps에서 200ps로 단축할 수 있습니다.
클럭 주파수가 1GHz ➔ 5GHz로 5배 향상되며, 파이프라인이 가득 차면(Steady-state) 매 200ps마다 1개씩 명령어가 완료됩니다.
3. 하드웨어 엔지니어링 핵심 멘탈 모델
Latency vs Throughput: 단일 명령어의 시작부터 종료까지 걸리는 물리 시간(Latency)은 줄어들지 않거나 파이프라인 레지스터 지연으로 미세하게 늘어납니다. 그러나 CPU 전체 관점에서 단위 시간당 배출되는 명령어 개수(Throughput)는 스테이지 개수(k)에 비례하여 비약적으로 폭증합니다.

🛡️ 파이프라인 레지스터(Pipeline Registers)의 핵심 책무
• 스테이지 사이에 배치된 IF/ID, ID/EX, EX/MEM, MEM/WB 레지스터
• 매 클럭 상승 엣지(Clock Rising Edge)에만 중간 연산값과 제어 신호를 동기화 래치(Latch)
• 다음 명령어가 이전 명령어의 실행 중간값을 덮어쓰지 못하도록 전기적 차단벽(Firewall) 형성
1. 5대 파이프라인 스테이지 상세 분석
• IF: PC가 가리키는 메모리에서 32비트 명령어 인출 후 PC += 4 전진
• ID: 32비트 opcode 해독, 레지스터 파일에서 소스 피연산자(Rn, Rm) 값 판독
• EX: ALU를 통해 산술·논리 연산 수행, 메모리 주소 계산, 조건 분기 판정
• MEM: 데이터 캐시(D-Cache)에 로드(LDR) 또는 저장(STR) 수행
• WB: 최종 연산 결과 또는 메모리 로드 값을 목적지 레지스터(Rd)에 영구 기록
2. 하드웨어 격리와 중간 레지스터의 필연성
스테이지 간 중간 레지스터가 없다면, EX 단계가 ADD를 연산하는 도중에 뒤따라온 SUB 명령어가 레지스터 판독 값을 덮어써서 데이터 오염이 발생합니다.
파이프라인 레지스터는 각 스테이지의 입출력 신호를 1클럭 동안 단단히 붙잡아두어 5개 명령어가 서로 간섭 없이 동시 실행되도록 보장합니다.
3. 이상적 Throughput: IPC = 1.0
5사이클이 지나 파이프라인이 가득 채워지면(Pipeline Filled), 매 클럭마다 1개씩 WB가 완료됩니다.
이로써 클럭당 명령어 처리 수(IPC, Instructions Per Cycle)는 이론적 상한선인 1.0에 도달합니다.

03. 파이프라인 3대 해저드와 하드웨어 극복 기법

순차 실행 환상을 깨뜨리는 구조적·데이터·제어 충돌과 이를 해결하는 포워딩, 분기 예측, 플러시 메커니즘

3 MAJOR PIPELINE HAZARDS
1. 구조적 해저드 (Structural Hazard) 자원 경합
동일 하드웨어 유닛을 두 개 이상의 명령어가 동시 요구 (예: 단일 메모리에서 IF와 MEM 단계 동시 충돌).
해결: 하버드 아키텍처 (명령어 I-Cache와 데이터 D-Cache 물리 분리)
2. 데이터 해저드 (Data Hazard: RAW) Read-After-Write
앞선 연산(add x0)의 결과가 레지스터에 기록(WB)되기 전에 뒷 연산(sub x3, x0)이 읽으려 함.
해결: 하드웨어 포워딩/바이패싱 (ALU 출력을 다음 EX MUX로 직결)
3. 제어 해저드 (Control / Branch Hazard) 분기 판정 지연
조건 분기문(b.eq) 판정이 EX 단계에서 날 때까지 다음 Fetch할 PC 주소를 알 수 없음.
해결: 분기 예측기 + 오예측 시 파이프라인 플러시(Flush 버블)
1. 하드웨어 포워딩 (Forwarding / Bypassing)의 마법
RAW 데이터 해저드를 레지스터 파일 쓰기(WB)까지 기다려 해결하려면 2~3클럭의 Stall(파이프라인 정지)이 발생하여 성능이 반토막 납니다.
하드웨어는 EX 단계 연산이 끝난 즉시 ALU 출력 버스에서 와이어를 직접 따서, 다음 사이클에 실행되는 후속 명령어의 ALU 입력 MUX로 직결 공급합니다. 이로써 0사이클 지연(Stall 없음)으로 RAW 문제를 극복합니다.
2. 로드-사용 해저드 (Load-Use Data Hazard)
단, LDR x0, [sp]처럼 메모리에서 읽어오는 값은 MEM 단계(사이클 4)가 끝나야 비로소 도착합니다.
따라서 바로 다음 명령어가 해당 값을 쓰려면 어떠한 포워딩으로도 막을 수 없는 1사이클 하드웨어 인터록(Stall Bubble)이 불가피합니다.
3. 분기 예측 실패와 파이프라인 플러시 페널티
최신 CPU는 분기 예측기(Branch Predictor)를 통해 분기 여부를 투기적으로 추측(Speculative Execution)하여 파이프라인을 멈추지 않습니다.
그러나 예측이 빗나가면(Misprediction), 이미 파이프라인에 잘못 투입된 명령어들을 즉시 NOP 버블로 소각하는 파이프라인 플러시(Pipeline Flush)가 발동하며 3~15 사이클의 막대한 페널티를 치릅니다.
