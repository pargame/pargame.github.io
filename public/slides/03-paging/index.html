1. 프로세스 격리와 가상 주소 공간의 탄생

동일한 가상 주소(0x0040_1000)를 접근해도 MMU가 물리 메모리를 완벽히 격리하는 하드웨어 원리

// 프로세스 격리 검증 어셈블리 파이프라인
0x1000: [Proc A] mov [0x00401000], #42 // A: 42 쓰기
0x1004: [Proc A] ldr w0, [0x00401000] // w0 = 42 로드
0x2000: [Kernel] msr ttbr0_el1, x20 // B로 스위칭(CR3)
0x3000: [Proc B] mov [0x00401000], #99 // B: 99 쓰기
0x2004: [Kernel] msr ttbr0_el1, x10 // A로 복귀(CR3)
0x1008: [Proc A] ldr w0, [0x00401000] // w0 = 42 불변!

2. 4KB 페이징과 12비트 오프셋(Offset) 비트 분해

가상 주소 변환의 핵심: 하위 12비트는 100% 보존되고, 상위 VPN만 변환된다

// 48비트 가상 주소(VA) 비트 슬라이싱 구조
상위 36비트 [47:12] 하위 12비트 [11:0]
VPN: 0x7FFF_5FB0
+ 0x8AC
왜 정확히 12비트인가?
페이지 크기가 4KB ($4,096\text{ Bytes} = 2^{12}$)이므로, 4,096바이트 내부의 위치를 지정하기 위해 오프셋은 정확히 12비트가 필요합니다.
실시간 주소 프리셋 테스트:
1단계: 가상 주소 (VA) 입력 분해
가상 페이지 번호 (VPN) 0x7FFF_5FB0
페이지 내부 오프셋 (Offset 12비트) 0x8AC (2,220번째 바이트)
2단계: MMU 변환 결과 (Physical RAM)
물리 프레임 번호 (PFN) 0x0001_8C40 (RAM Frame)
최종 물리 주소 (PA = PFN + Offset) 0x0001_8C40_08AC

✓ 하위 12비트 오프셋은 변환 없이 그대로 통과하며, 오직 VPN만 페이지 테이블을 통해 PFN으로 변환됩니다.

4. C++ 개발자가 만나는 하드웨어 예외 (Segmentation Fault)

PTE 보호 비트(Protection Bits)와 운영체제 SIGSEGV의 실시간 연동

// C++ 버그 시나리오 선택
int* ptr = nullptr; *ptr = 42; // <-- 0번 페이지 접근
PTE (Page Table Entry) 플래그 비트 하드웨어 검사
Present 0
R / W 1
User 1
NX (실행) 0
CPU ➔ OS 커널 시그널 처리 파이프라인
인터럽트 결과
CPU Vector #14 (Page Fault) ➔ SIGSEGV

0번 가상 주소는 OS가 의도적으로 매핑하지 않아, nullptr 접근 즉시 CPU 하드웨어가 SIGSEGV로 프로세스를 보호 종료합니다.
