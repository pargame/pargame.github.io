동일한 가상 주소(@5120)를 쓰더라도 MMU와 각 프로세스의 페이지 테이블을 거쳐 서로 다른 물리 프레임으로 안전하게 분리 변환됩니다.
1. 독립 가상 주소 공간 (Virtual Address Space)
운영체제는 각 프로세스에게 0번지부터 시작하는 64비트 독립 주소 공간을 제공합니다. 개발자는 다른 프로그램의 메모리 배치나 충돌 위험 없이 전용 메모리를 독점하듯 프로그램을 작성할 수 있습니다.
🛡️ 2. 하드웨어 수준의 메모리 보호 (Memory Protection)
MMU(Memory Management Unit)는 읽기/쓰기/실행 권한(R/W/X)을 하드웨어 수준에서 검사합니다. 허가되지 않은 영역이나 커널 영역 침범 시 즉각 하드웨어 트랩(Fault)을 발생시켜 전체 시스템 오염을 차단합니다.
📦 3. 물리 RAM 크기의 한계 극복 (Demand Paging)
실제 물리 RAM이 16GB에 불과하더라도, 활성 프로세스들의 총 가상 공간은 수십 GB 이상으로 확장될 수 있습니다. 현재 실행에 필요한 페이지만 물리 메모리에 상주시키고, 나머지는 스왑 영역으로 유연하게 관리합니다.

02. 페이징(Paging) 메커니즘과 10진수 주소 변환

고정 크기 분할을 통한 외부 단편화 해결과 오프셋(Offset) 불변 변환 원리

가상 주소 (VA) @5120 ➔ [Page 5] + [Offset 120]
페이지 테이블 (Page Table) VPN 5 ➔ PFN 2 물리 Frame 2 매핑
물리 주소 (PA) @2120 ➔ [Frame 2] + [Offset 120]
10진수 주소 변환 공식 (Page Size = 1,000B)
VA = (VPN × 1,000) + Offset ➔ PA = (PFN × 1,000) + Offset
★ 오프셋(Offset) 불변 원리:
가상 페이지와 물리 프레임 크기가 1,000B로 일치하므로, 시작점으로부터의 상대적 변위(Offset 120)는 변환 과정에서 손실 없이 그대로 보존됩니다.
고정 크기 분할 (Fixed-Size Paging)
가변 크기 할당 시 메모리 사이에 빈틈이 생기는 외부 단편화(External Fragmentation)를 방지하기 위해, 가상 메모리는 고정 크기 페이지(Page)로, 물리 메모리는 동일 크기의 프레임(Frame)으로 균일하게 분할합니다.
🔍 VPN(Virtual Page Number)과 오프셋(Offset)
가상 주소는 상위 비트의 페이지 번호(VPN)와 하위 비트의 오프셋(Offset)으로 분해됩니다. MMU는 VPN을 페이지 테이블에서 찾아 물리 프레임 번호(PFN)로 치환하고, 오프셋은 그대로 이어 붙여 물리 주소를 완성합니다.
💡 현실 아키텍처 연계 (ARM64 / x86-64 표준 4KB)
학습 모델에서는 직관적 이해를 위해 1,000B 모델을 사용했으나, 실제 하드웨어 표준 페이지 크기는 4KB(4,096바이트 = 2¹²B)입니다. 64비트 주소 체계에서 하위 12비트(2¹² = 4,096)가 오프셋을 형성하며, 상위 비트들이 페이지 테이블 순회에 사용됩니다.
📖 페이지 테이블 하드웨어 레지스터 연동
운영체제는 각 프로세스마다 페이지 매핑 테이블을 구성하고, 그 시작 주소를 CPU 제어 레지스터(ARM64 TTBR0_EL1, x86-64 CR3)에 적재하여 하드웨어 MMU가 실시간으로 참조하도록 합니다.

03. TLB 고속 주소 캐시와 요구 페이징(Demand Paging)

2중 메모리 접근 병목의 필연적 극복과 Valid 비트 기반 지연 메모리 할당

⚠️ 2중 메모리 접근 병목 (Double Memory Access Problem)
페이지 테이블도 RAM에 상주하므로, TLB가 없다면 가상 주소 접근 1회마다 [1. 주소 변환 RAM 참조(~100ns)] + [2. 실제 데이터 인출 RAM 참조(~100ns)] = 총 2회 RAM 접근(~200ns)이 강제되어 속도가 반토막 납니다.
1순위: MMU 내부 TLB 캐시 조회 0.5ns (TLB Hit, SRAM 고속)
2순위: RAM 페이지 테이블 순회 (Table Walk) ~100ns (DRAM 참조)
3순위: 물리 메모리 미할당 감지 (Valid=0) Page Fault 예외 발동
시간적·공간적 지역성(Locality) 덕분에 99% 이상의 주소 변환이 TLB 캐시(0.5ns) 내에서 즉시 해결되어 2중 접근 병목을 완벽히 무력화합니다.
TLB (Translation Lookaside Buffer)
2중 RAM 접근 지연을 방지하기 위해 CPU MMU 내부에 탑재된 초고속 하드웨어 SRAM 캐시입니다. 최근 변환된 VPN ➔ PFN 매핑을 저장하여 수 사이클(0.5ns) 이내에 물리 주소를 확정합니다.
🚚 요구 페이징(Demand Paging)과 지연 할당
프로그램이 메모리를 요청(예: malloc)하더라도 OS는 물리 프레임을 즉시 낭비하지 않고 페이지 테이블에 Valid=0으로 표기합니다. 실제로 데이터 쓰기가 일어나는 순간 하드웨어 Page Fault 예외가 발생하며, 커널이 빈 프레임을 즉석에서 할당한 후 명령어를 재실행합니다.
⛔ 유효하지 않은 주소 접근 (Segmentation Fault)
접근 권한이 없거나 할당되지 않은 0번지(nullptr) 등에 접근할 경우, OS는 요구 페이징을 수행하지 않고 프로세스에 SIGSEGV 시그널을 전달하여 시스템 무결성을 지키고 프로세스를 안전하게 종료합니다.
