1. 프로세스와 CPU 하드웨어의 관계

운영체제가 부여한 거대한 가상 메모리(128TB)와 CPU 코어가 독점하는 초고속 레지스터 세트(256B)

💡 10진수 교육용 주소 모델: 64비트 16진수 대신 원리 이해를 위해 @1000, @8000 등 10진수 주소를 적용했습니다
🏢 가상 메모리 공간 (RAM) 128 TB (광활한 공간)

운영체제(OS)는 각 프로세스에게 "너 혼자 128TB 전체를 독점하고 있다"는 환상의 가상 주소 공간을 부여합니다.

Stack 영역
함수 호출, 지역 변수 (⬇️ @8000, 8MB 한계)
Heap 영역
동적 메모리 할당 (malloc / new)
Data / BSS
전역 변수 및 정적 변수 (rw-: 읽기/쓰기 가능)
Code (Text)
컴파일된 기계어 바이너리 (▶ @1000, r-x: 읽기/실행 전용, 위변조 방지)
⚡ CPU 코어 내부 물리 레지스터 0.2 나노초 (초고속)

CPU 코어 내부에 물리적으로 내장된 단 32개의 64비트 메모지입니다. 스레드가 코어에서 실행되는 동안 오직 그 스레드만 독점합니다.

코어 활성 레지스터 뱅크 (총 256 바이트 남짓)
PC: ▶ @1000 SP: ⬇️ @8000 LR: @0 X0 ~ X30 (31개)
  • 극강의 속도: RAM보다 수백 배 빠른 0~1사이클(0.2ns) 접근
  • 주소 없음: 주소(`&`)를 딸 수 없으며, 레지스터 이름(`x0`, `pc`)으로 직접 지목
  • 크기 한계: 32개 × 8바이트 = 단 256바이트로 모든 계산을 수행
🔄 하드웨어 브릿지: 컨텍스트 스위칭 (Context Switching)의 본질 OS 스케줄러 ➔ CPU 하드웨어 래치 동기화
1. 기존 스레드 일시 중단 (Save):
CPU 코어의 32개 물리 레지스터 값을 해당 스레드의 RAM 스택/TCB 메모리로 그대로 복사해 백업합니다.
2. 새 스레드 코어 안착 (Restore):
새 스레드가 과거에 백업해 두었던 레지스터 값들을 코어로 로드하고, PC가 가리키는 지점부터 즉시 실행을 재개합니다.

2. 핵심 특수 레지스터 4총사

프로그램의 실행 흐름(흐름 제어, 스택, 함수 호출)을 전담하는 핵심 하드웨어 장치

PC 64-bit
Program Counter
"다음에 실행할 기계어의 메모리 주소"
CPU가 명령어를 한 줄 읽어올 때마다 자동으로 4바이트씩 전진합니다. 점프 명령어(`B`, `BL`)를 만나면 목적지 주소로 덮어써집니다.
SP 64-bit
Stack Pointer (X31)
"현재 스택 메모리의 최상단 유효 주소 번지"
스택은 높은 번지(@8000)에서 낮은 번지(@7984)로 거꾸로 자라므로 뺄셈(sub sp, sp, #16)으로 주소를 깎아 공간을 확보하고, 함수가 끝나면 덧셈(add sp, sp, #16)으로 복원합니다. (16바이트 정렬 필수)
LR (X30) 64-bit
Link Register
"함수가 끝나고 나중에 돌아올 복귀 주소"
`bl _main`으로 함수를 부르면 다음 줄 주소가 여기에 백업되며, 함수 끝에서 `ret`을 실행하면 이 LR 값이 다시 PC로 복사되어 복귀합니다.
FP (X29) 64-bit
Frame Pointer
"현재 함수의 스택 프레임 기준 베이스 주소"
SP가 함수 안에서 수시로 오르내릴 때, 지역 변수들의 안정적인 기준점 역할을 하여 디버거가 함수 호출 스택(콜스택)을 추적할 수 있게 돕습니다.

3. 범용 레지스터 (X0 ~ X28)

계산, 함수 인자 전달, 임시 저장을 위한 31개의 64비트 일꾼 레지스터

X0 ~ X7 함수 인자 / 반환

함수 호출 규약 (ABI):

• X0: 함수의 리턴값(Return Value)이 담기는 전 세계 표준 자리!

• X0 ~ X7: 함수를 호출할 때 1번째~8번째 매개변수를 담아서 전달합니다.

X9 ~ X15 임시 (Scratch)

호출자 보존 (Caller-saved):

함수 안에서 사칙연산(`ADD`, `MUL`) 계산용으로 자유롭게 막 쓰고 버릴 수 있는 임시 메모지입니다.

다른 함수를 호출하면 값이 날아갈 수 있습니다.

X19 ~ X28 영구 보존

피호출자 보존 (Callee-saved):

중요한 변수를 담는 방입니다.

함수가 이 레지스터를 쓰고 싶다면, 반드시 원래 있던 값을 스택에 백업해 두고, 함수가 끝날 때 원래대로 복원해 줘야 합니다.

🔬 하드웨어 레지스터 분할: 64비트(X0)와 32비트(W0)의 물리 구조
W0는 X0의 하위 4바이트 물리 별칭
Bit 63 Bit 32 Bit 31 Bit 0
상위 32비트 [63:32] (Upper 4B)
W0 쓸 때 0으로 클리어 (Zero-Ext)
하위 32비트 [31:0] (W0: 4B)
32-bit int 연산 공간
⮜────────────── X0 전체 (64-bit, 8바이트 메모리 주소 / 포인터 / int64) ──────────────⮞
💡 물리 하드웨어의 원리: W0는 별개의 회로가 아니라 X0 레지스터의 하위 32가닥 구리선을 부르는 이름입니다.
ARM64 하드웨어 규칙에 따라 `mov w0, #5`처럼 W 레지스터에 값을 쓰면, 상위 32비트는 자동으로 0으로 지워집니다(Zero-extension).

4. 특수 하드웨어 & 실수/시스템 레지스터

0값 전용 하드웨어 접지, IEEE 754 부동소수점, 페이지 테이블 주소

XZR / WZR Zero Register

"읽으면 항상 0, 쓰면 버려짐"

하드웨어 접지선(GND)처럼 물리적으로 0으로 묶여있는 마법의 레지스터입니다.

변수를 0으로 초기화하거나, 결과값을 버리고 플래그만 세팅할 때 씁니다.

D0 ~ D31 (V) IEEE 754 FPU

"실수(소수점) & 벡터 연산기"

정수 레지스터(X0)와 물리 회로가 아예 다른 부동소수점 전용 64비트 레지스터입니다.

C 언어의 double pi = 3.14; 같은 실수를 다룰 때, 정수용 X0 대신 이 전용 D0 레지스터(FPU)에 값을 얹어 고속 계산합니다.

TTBR0_EL1 시스템 레지스터

"L0 페이지 테이블 주소 보관함"

후속 파트에서 다룰 가상 메모리 변환 장부(페이지 테이블)의 최상위 뿌리 시작 주소를 담고 있는 CPU 내부 특수 레지스터입니다.

오직 OS 커널만 이 레지스터를 수정할 수 있습니다.

5. 라이브 시뮬레이터: 함수 호출과 레지스터 변화

`main()`이 `add_numbers(5, 7)`를 호출하고 복귀할 때 레지스터들이 바뀌는 실시간 과정

// ARM64 어셈블리 실행 파이프라인
_main:// 프로그램 진입점 (Entry)
▶ @1000 mov w0, #5// 인자 1 (5)
▶ @1004 mov w1, #7// 인자 2 (7)
▶ @1008 bl _add_numbers// 함수 호출 (LR 백업)
▶ @1012 str w0, [sp, #8]// 결과(12) 스택 저장
...
_add_numbers:// 피호출 함수
▶ @2000 add w0, w0, w1// 5 + 7 = 12
▶ @2004 ret// LR로 복귀!

PC▶ @1000
LR (X30)대기 (@0)
W0 (결과/인자1)0
W1 (인자2)0
SP (Stack Pointer)⬇️ @8000
스택 메모리 프레임 [SP 오프셋]
[SP, #8] 결과값 보관
(비어있음 @8008)
[SP, #0] 호출자 프레임
