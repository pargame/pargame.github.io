01. 가상 메모리의 필요성과 독립 주소 공간

프로세스 간 메모리 충돌 방지, 하드웨어 수준의 메모리 보호 및 가상 주소 공간 격리

프로세스 A 가상 공간
64비트 독립 주소 공간
VA @5120
Page Table A 참조
프로세스 B 가상 공간
64비트 독립 주소 공간
VA @5120
Page Table B 참조
물리 메모리 (Physical RAM) 주소 분리
A의 물리 주소: Frame 2 (@2120) B의 물리 주소: Frame 7 (@7120)
동일한 가상 주소(@5120)를 쓰더라도 각 프로세스의 페이지 테이블을 거치며 서로 다른 물리 프레임으로 안전하게 분리 변환됩니다.
독립 가상 주소 공간 (Virtual Address Space)
운영체제는 각 프로세스에게 0번지부터 시작하는 고유한 64비트 주소 공간을 제공합니다. 개발자는 다른 프로세스의 메모리 배치나 물리 RAM의 실제 주소를 신경 쓰지 않고 독립된 환경에서 프로그램을 작성할 수 있습니다.
🛡️ 하드웨어 수준의 메모리 보호 (Memory Protection)
가상 메모리가 없다면 프로세스 하나가 포인터 버그로 다른 프로세스나 운영체제 커널의 코드를 덮어써 시스템 전체가 크래시됩니다. MMU(Memory Management Unit)는 허가되지 않은 메모리 영역이나 읽기 전용 코드 영역에 쓰기 접근이 발생할 때 즉시 **하드웨어 트랩(Fault)**을 발생시켜 시스템을 보호합니다.
📦 물리 RAM 크기의 한계 극복
실제 물리 RAM이 16GB에 불과하더라도, 활성 프로세스들의 총 가상 주소 공간은 수십 GB 이상으로 확장될 수 있습니다. 현재 실행에 필요한 페이지만 물리 메모리에 상주시키고, 나머지는 스왑 영역으로 유연하게 관리합니다.

02. 페이징(Paging) 메커니즘과 10진수 주소 변환

고정 크기 페이지 분할을 통한 외부 단편화 제거와 VPN ➔ PFN 주소 변환 원리

가상 주소 (VA) @5120 ➔ [Page 5] + [Offset 120]
페이지 테이블 (Page Table) VPN 5 ➔ PFN 2 물리 Frame 2 매핑
물리 주소 (PA) @2120 ➔ [Frame 2] + [Offset 120]
10진수 주소 변환 공식 (Page Size = 1,000B)
VA = (VPN × 1,000) + Offset ➔ PA = (PFN × 1,000) + Offset
오프셋(Offset 120)은 변환 과정에서 손실 없이 100% 보존됩니다.
고정 크기 분할 (Fixed-Size Paging)
메모리를 임의의 가변 크기로 할당하면 메모리 사이에 빈틈이 생겨 사용하지 못하는 **외부 단편화(External Fragmentation)**가 발생합니다. 페이징 기법은 가상 메모리를 고정 크기의 **페이지(Page)**로, 물리 메모리를 동일 크기의 **프레임(Frame)**으로 균일하게 나누어 메모리 활용률을 극대화합니다.
🔍 VPN(Virtual Page Number)과 오프셋(Offset)
가상 주소는 상위 비트의 페이지 번호(VPN)와 하위 비트의 오프셋(Offset)으로 분해됩니다. MMU는 VPN을 페이지 테이블에서 찾아 물리 프레임 번호(PFN)로 치환하고, 페이지 내부에서의 상대 위치인 오프셋은 그대로 이어 붙여 물리 주소를 완성합니다.
📖 페이지 테이블(Page Table)의 하드웨어 연동
운영체제는 각 프로세스마다 페이지 매핑 테이블을 구성하고, 그 시작 주소를 CPU의 특정 제어 레지스터(ARM64의 TTBR0_EL1, x86-64의 CR3)에 적재하여 하드웨어 MMU가 실시간으로 참조할 수 있도록 합니다.

03. TLB 고속 주소 캐시와 요구 페이징(Demand Paging)

MMU 내부 TLB 캐시의 주소 변환 가속과 유효 비트(Valid Bit)를 활용한 지연 메모리 할당

1순위: MMU 내부 TLB 캐시 조회 0.5ns (TLB Hit)
2순위: RAM 페이지 테이블 순회 (Table Walk) ~100ns (RAM 참조)
3순위: 물리 메모리 미할당 감지 (Valid=0) Page Fault 예외 발동
시간적·공간적 지역성(Locality) 덕분에 99% 이상의 주소 변환이 TLB 캐시(0.5ns) 내에서 즉시 해결됩니다.
TLB (Translation Lookaside Buffer)
메모리에 접근할 때마다 매번 RAM에 위치한 페이지 테이블을 다단계로 순회하면 실행 속도가 크게 저하됩니다. MMU 내부의 고속 SRAM 캐시인 TLB는 최근 변환된 VPN ➔ PFN 매핑을 저장하여 수 사이클 이내에 물리 주소를 확정합니다.
🚚 요구 페이징(Demand Paging)과 지연 할당
프로그램이 메모리를 요청(예: malloc)하더라도 OS는 물리 프레임을 즉시 낭비하지 않고 페이지 테이블에 Valid=0으로 표기합니다. 실제로 데이터 쓰기가 일어나는 순간 하드웨어 Page Fault 예외가 발생하며, 커널이 빈 프레임을 즉석에서 할당한 후 명령어를 재실행합니다.
⛔ 유효하지 않은 주소 접근 (Segmentation Fault)
접근 권한이 없거나 할당되지 않은 0번지(nullptr) 등에 접근할 경우, OS는 요구 페이징을 수행하지 않고 프로세스에 SIGSEGV 시그널을 전달하여 시스템 무결성을 지키고 프로세스를 안전하게 종료합니다.
