## 2. 파일 작업 한 스텝은 얼마나 걸리나? (중앙값과 P90)

로그의 `PLANNER_RESPONSE.created_at`은 생성 시작 시각입니다. 따라서 다음 스텝까지의 간격은 순수 추론 시간이 아니라 **생성(thinking 포함) + 도구 실행이 합쳐진 1스텝 왕복 시간**입니다.

실행 시간 편차가 큰 `run_command`와 사용자 대기가 섞이는 `ask_question`은 제외했습니다. <strong>파일 읽기·편집 전용 스텝(<code>read_file</code> / <code>edit_file</code> / <code>write_file</code>)</strong>만 0~40초 같은 선형 축에 올렸습니다.

## 5. 결론: 모델별 체감 정리

세 차트를 함께 보면 "한 턴의 속도"보다 **병렬 배치와 꼬리 지연 안정성**이 체감 속도에 더 크게 작용한 것으로 보입니다.

이번 로그에서 각 모델이 주로 맡았던 작업과 관찰된 리듬을 정리하면 다음과 같습니다.

* <strong><code>4 Hydrogen (Medium)</code></strong> — 곰팡이 프로젝트 C++ 구현과 문서 작성. 중앙값 6초 · P90 11초의 좁은 왕복 구간과 24.9% 병렬 배치.
* <strong><code>4 Neon (Medium)</code></strong> — 블로그 3단 구조 리팩터링과 Notion MCP 연동. 40.3% 병렬 배치(평균 2.08개/턴)로 다중 파일 편집을 묶어 처리.
* <strong><code>3.8 Flash</code></strong> — 초기 터미널 점검·빌드와 단발성 조사. 중앙값 5초로 빠르지만 1턴 1도구 순차 호출 위주.
* <strong><code>4 Argon</code></strong> — UE 5.9 호환성·툴체인 심층 조사. 중앙값 10~11.5초, P90 31~35초로 스텝당 호흡이 가장 길었음.
