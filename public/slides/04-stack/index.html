01. 스택 메모리의 개념과 LIFO 원리

왜 컴퓨터는 함수를 실행할 때 메모리를 '접시 쌓기'처럼 관리할까요? 높은 주소에서 낮은 주소로 자라나는 원리

🔻 스택 영역 (Stack) - 아래로 자람 (↓) @8000 (Top of Memory)
자유 공간 (Free Memory Gap) - 스택과 힙이 서로 마주보며 성장
🔺 힙 영역 (Heap) - 위로 자람 (↑) @3000 (동적 할당)
데이터 영역 (BSS / Data) 전역·정적 변수
코드 영역 (Text/Code) @1000 (기계어 명령어)
스택은 메모리의 가장 높은 번지(@8000)에서 시작해 데이터가 쌓일 때마다 @7984, @7968처럼 아래로 감소합니다.
🍽️ 일상 비유: 뷔페의 접시 쌓기 (LIFO)
뷔페에서 접시를 채울 때 맨 위에 얹고(Push), 손님도 맨 위 접시부터 집어가듯(Pop), 가장 나중에 호출된 함수가 가장 먼저 실행을 마치고 나가는 원리(Last-In, First-Out)와 완벽히 같습니다.
💡 왜 스택은 높은 주소에서 낮은 주소로 자랄까요?
프로세스 메모리를 가장 알뜰하게 쓰기 위해서입니다. 자유롭게 크기가 늘어나는 힙(Heap)은 아래에서 위로 자라고, 스택(Stack)은 맨 위에서 아래로 자라납니다. 서로 마주보고 자라기 때문에 사전 경계 없이 빈 메모리를 유연하게 나눠 쓸 수 있습니다.
⚙️ CPU 레지스터: Stack Pointer (SP)
CPU의 SP(스택 포인터) 레지스터는 항상 현재 스택의 맨 꼭대기(가장 낮은 주소)를 실시간으로 가리킵니다.
  • 함수 호출 시 (Push): SP = SP - 프레임 크기 (주소 감소)
  • 함수 반환 시 (Pop): SP = SP + 프레임 크기 (주소 복원)

02. 스택 프레임의 해부도와 FP, SP 레지스터

함수 하나가 실행될 때 메모리에는 어떤 정보들이 블록처럼 포장될까요? 기준점(FP)과 꼭대기(SP)의 협력

📦 스택 프레임 단면도 (Stack Frame) 높은 주소 (위) ➔ 낮은 주소 (아래)
매개변수 (Arguments) a = 10, b = 20
복귀 주소 (Return Address / LR) PC @1020 (돌아갈 코드)
이전 프레임 포인터 (Saved FP) ⚓ @8000 (부모의 FP)
지역 변수 (Local Variables) int sum = 30
현재 스택 꼭대기 (Top of Stack) SP ➔ @7936
함수 내에서 값이 계속 바뀌어도 FP(Frame Pointer)라는 고정 닻을 기준으로 FP - 8, FP - 16처럼 안정적으로 지역 변수를 찾아냅니다.
🧩 스택 프레임의 3대 핵심 구성 요소
  • 복귀 주소 (Return Address): 함수가 끝났을 때 CPU가 어느 코드 번지(PC)로 되돌아가 실행을 이어갈지 적어둔 메모리 표식입니다.
  • 이전 프레임 포인터 (Saved FP): 나를 부른 부모 함수의 기준점 위치를 기록해 두어, 함수 반환 시 부모의 프레임을 단번에 복원합니다.
  • 지역 변수 및 임시 값 (Locals): 함수 안에서 선언된 변수들이 자리 잡으며, 함수가 반환되면 1초 만에 일괄 해제됩니다.
⚓ FP(Frame Pointer) vs SP(Stack Pointer)의 차이
SP는 수식 계산이나 추가 push에 따라 시시각각 위아래로 움직입니다. 만약 기준점 없이 SP로만 변수를 찾으려면 오프셋 계산이 복잡해집니다. 컴파일러는 함수 진입 시점의 위치를 FP(x29 레지스터)에 고정시켜 흔들림 없는 닻으로 사용합니다.
⚡ 초고속 메모리 할당의 비결
스택에서의 메모리 할당은 힙(malloc)처럼 복잡한 빈 공간 탐색이 전혀 없습니다. 단지 CPU 레지스터 값을 한 번 빼거나 더하는 것(sub sp, sp, #32)만으로 0.001나노초 만에 할당과 해제가 끝납니다.

03. 스택 오버플로우(Stack Overflow)와 방어 기법

함수가 끝나지 않고 계속 스택을 쌓으면 어떤 일이 벌어질까요? 한계선(Limit) 돌파와 운영체제의 보호막

정상 스택 영역 (Normal Stack) @8000 ~ @7400
⚠️ 스택 한계선 (Stack Limit 경계) @7200
💥 GUARD PAGE (접근 금지 보호벽)
침범 방지 격리 구역 (보호선)
힙 메모리 영역 (Heap) @3000 ~ @4500
재귀 호출이 무한 반복되어 스택이 @7200 가드 페이지를 밟는 순간, MMU 하드웨어 트랩이 터지며 OS가 프로세스를 강제 종료합니다.
🚨 왜 스택 오버플로우가 발생할까요?
  • 탈출 조건 없는 무한 재귀 (Infinite Recursion): if (n == 0) return; 같은 종료 조건이 빠져 함수가 자신을 끝없이 호출할 때.
  • 과도하게 큰 지역 변수 선언: 스택 크기는 보통 수 MB(macOS 약 8MB)로 제한적인데, int big[2000000];처럼 거대한 배열을 스택에 할당할 때.
🛡️ 운영체제의 안전장치: 가드 페이지 (Guard Page)
스택이 무한정 커져서 힙(Heap)이나 중요한 시스템 메모리를 덮어쓰지 못하도록, OS는 스택 끝자락에 읽기·쓰기가 전면 차단된 빈 페이지(Guard Page)를 심어둡니다. CPU가 이 주소를 건드리면 즉각 하드웨어 Fault가 발생하여 Segmentation Fault (SIGSEGV)로 안전하게 종료됩니다.
🐤 컴파일러의 보초병: 스택 카나리 (Stack Canary)
과거 해커들이 버퍼 오버플로우로 복귀 주소(Return Address)를 조작해 악성 코드로 점프시키는 해킹을 막기 위해, 컴파일러는 복귀 주소 바로 앞에 무작위 비밀값(카나리)을 심어둡니다. 함수 종료 직전 이 값이 1비트라도 바뀌었다면 공격으로 간주하고 프로세스를 자폭시킵니다.
