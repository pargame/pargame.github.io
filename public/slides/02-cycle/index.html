01. 기계어와 클럭(Clock) 동기화 메커니즘

2진수 비트열로 표현되는 명령어와, 수억 개의 플립플롭을 일제히 전진시키는 클럭 펄스

⚡ 클럭 생성기: 4.0 GHz 발진 신호 (Square Wave)
주기 T = 1 / f = 0.25 나노초 (0.25ns)
ARM64 32비트 기계어 구조: add w0, w1, w2
Opcode: 0x0B (ADD) Rn: W1 | Rm: W2 Rd: W0
클럭 신호의 상승 에지(Rising Edge) 순간에만 레지스터의 데이터가 래치(Latch)되어 회로의 레이스 컨디션을 방지합니다.
동기식 디지털 논리회로 (Synchronous Logic)
CPU 내부의 수억 개 트랜지스터 게이트는 신호 전달 지연(Propagation Delay) 시간이 서로 다릅니다. 주기적인 클럭 신호(Clock Signal)를 통해 모든 플립플롭이 동일한 타이밍에 입력을 래치함으로써 계산 오류와 신호 충돌을 원천 차단합니다.
💡 기계어(Machine Code)의 비트 구조
기계어는 CPU 제어장치가 하드웨어 신호로 분해할 수 있도록 규격화된 2진수 비트열입니다.
  • Opcode (연산 코드): 수행할 마이크로 연산(ADD, SUB, LDR 등)을 결정하는 멀티플렉서 제어선
  • 피연산자 레지스터 인덱스: 소스 및 목적지 레지스터 주소 번호
⚡ 클럭 주파수(Clock Frequency)와 실행 시간
4.0 GHz CPU는 초당 40억 회의 클럭 펄스를 발생시킵니다. 1 사이클(Cycle)은 0.25나노초(0.25ns)이며, 빛이 진공에서 약 7.5cm 이동하는 극도로 미세한 시간 단위입니다.

02. 명령어 사이클 4단계와 메모리 계층 레이턴시

Fetch ➔ Decode ➔ Execute ➔ Writeback 파이프라인과 L1 캐시 vs 메인 메모리(RAM) 레이턴시 격차

1. FETCH (명령어 인출) PC가 가리키는 메모리 주소에서 32비트 명령어 인출
2. DECODE (명령어 해독) Opcode 해석, 제어신호 생성 및 소스 레지스터(W1, W2) 판독
3. EXECUTE (연산 실행) ALU(산술논리연산장치) 가산 회로에서 15 + 27 = 42 연산
4. WRITEBACK (결과 기록) 결과값 42를 목적지 레지스터(W0) 플립플롭에 래치(Latch)
L1 캐시 레이턴시 1 Cycle (0.25 ns)
DDR5 RAM 메인 메모리 레이턴시 ~240 Cycles (60 ns) ➔ 파이프라인 스톨
인스트럭션 실행 사이클 (Instruction Execution Cycle)
CPU는 하나의 명령어를 실행하기 위해 하드웨어적으로 직렬화된 4단계를 순차적으로 거칩니다:
  • Fetch (인출): PC 주소로 메모리에 요청하여 기계어를 가져오고, PC는 다음 명령어를 가리키기 위해 4바이트 증가(+4)
  • Decode (해독): 제어장치가 Opcode를 해독하여 내부 데이터 패스(Datapath) 스위치 개폐
  • Execute (실행): ALU가 피연산자에 대해 산술/논리 연산 수행
  • Writeback (기록): 계산 결과를 목적지 레지스터에 기록하여 최종 상태 전이 완료
🐢 메모리 스톨(Memory Stall)과 캐시 계층 구조
CPU 코어가 0.25ns 주기로 고속 동작하더라도, 메인 메모리(DDR5 RAM)는 물리적 버스 거리와 커패시터 충전 시간 때문에 접근에 약 60ns (240 클럭 사이클)가 소요됩니다. 데이터가 도착할 때까지 파이프라인이 멈추는 **메모리 스톨(Stall)**을 방지하기 위해 CPU 내부 SRAM 기반의 L1/L2/L3 캐시가 필수적입니다.

03. 종합 인터랙티브 스튜디오: 명령어 사이클 시뮬레이터

[ANCHOR] 대기 중: [다음 단계]를 눌러 4단계 사이클을 시작하세요 READY
실행 명령어 (Arm64 기계어)

연산: W0 = W1(15) + W2(27) ➔ 42
1. FETCH: PC @1000 ➔ L1 캐시 기계어 인출 대기

3. EXECUTE: ALU 가산기 15 + 27 = 42 연산 대기
4. WRITEBACK: 연산 결과값 42를 W0에 래치 대기
