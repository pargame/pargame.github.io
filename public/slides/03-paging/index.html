1. 왜 가상 메모리(Virtual Memory)인가?

프로세스 독립 주소 공간과 하드웨어 메모리 보호(Protection) 메커니즘

문제: 물리 주소(Physical Memory) 직접 참조의 위험

과거 시스템처럼 모든 프로그램이 실제 물리 RAM 주소를 직접 읽고 쓴다면:

  • 주소 충돌: 프로세스 A와 B가 동일한 주소(0x1000)에 변수를 저장하려 할 때 덮어쓰기 발생
  • 보안 침해: 악성 프로그램이 다른 프로세스나 운영체제 커널의 비밀 메모리를 무단 탐색
  • 단편화(Fragmentation): 연속된 메모리 공간을 할당하기 어려워 실제 램이 남아돌아도 실행 불가
💡 해결책: 가상 주소 공간(Virtual Address Space)

운영체제와 CPU(MMU)는 각 프로세스에게 "나 혼자 테라바이트급 메모리를 독점한다"는 환상을 제공하고, 하드웨어 레벨에서 물리 RAM의 빈 조각(Frame)으로 안전하게 매핑합니다.

2. 4KB 페이징과 12비트 오프셋(Offset) 분해

가상 주소가 물리 주소로 바뀔 때, 실제로 변환되는 비트는 무엇인가?

핵심 원리: 왜 4KB 페이지일 때 오프셋이 12비트인가?

현대 OS와 CPU의 표준 페이지 크기는 4KB (4,096 Bytes)입니다. 4,096개의 서로 다른 바이트를 1대1로 식별하려면 정확히 12개의 비트 ($2^{12} = 4,096$)가 필요합니다. 따라서 모든 가상 주소는 [ 가상 페이지 번호 (VPN) ]와 [ 페이지 내부 오프셋 (12비트) ]로 나뉩니다.

VPN (가상 페이지 번호) // 상위 비트 변환 대상
0x0000_7FFF_5FB0
Offset (오프셋 12비트) // 변환 없이 100% 그대로 복사!
0x8AC
가상 주소 입력 시뮬레이션:
변환 전: Virtual Address
Virtual Address (48-bit)
0x7FFF_5FB0_08AC
➔ 상위 VPN(0x7FFF5FB0)은 MMU가 페이지 테이블을 조회하여 PFN(물리 프레임 번호)으로 치환합니다.
변환 후: Physical RAM Address
Physical Address in RAM
0x0001_8C40_08AC
➔ 주목: 하위 12비트 오프셋 0x8AC는 1비트도 변하지 않고 그대로 복사되었습니다!

3. MMU & TLB 하드웨어 변환 스튜디오

CPU 내부 TLB 캐시 조회부터 다단계 Page Table Walk, Page Fault까지

1단계: CPU 내부 TLB 캐시 대기 중

최근 변환된 [VPN ➔ PFN] 쌍을 보관하는 초고속 하드웨어 캐시 (접근 시간: 0.5ns)

VPN: 0x7FFF5F ➔ PFN: 0x18C4
VPN: 0x004020 ➔ PFN: 0x05E1
2단계: Page Table Walk (RAM) 미실행

TLB Miss 시 CPU가 CR3 레지스터를 읽고 4단계 페이지 테이블을 RAM에서 차례로 순회 (수십 ns 지연)

CR3 Reg: 0x0000_1000 (Root)
PTE: [Valid=1 | R/W=1 | PFN=0x18C4]
3단계: 물리 주소 확정 / 예외 READY

4. C++ 개발자가 만나는 하드웨어 예외 (Segmentation Fault)

PTE의 보호 비트(Protection Bits)와 운영체제 SIGSEGV 시그널의 원리

Page Table Entry (PTE)의 핵심 플래그 비트

각 페이지는 단순히 물리 주소만 갖는 것이 아니라, CPU가 강제하는 접근 권한 비트를 함께 저장합니다:

Present (P 비트, 0번 비트): 1이면 물리 램에 존재, 0이면 디스크에 있거나 미할당 (Page Fault 유발)
Read / Write (R/W 비트): 1이면 쓰기 허용, 0이면 읽기 전용 (코드 세그먼트에 쓰기 시도시 예외)
User / Supervisor (U/S 비트): 0이면 커널 전용 영역 (유저 모드 애플리케이션의 시스템 영역 침범 차단)
NX (No-Execute 비트): 스택/힙에 주입된 악성 셸코드 실행을 원천 차단하는 하드웨어 방어선
C++ 코드 버그와 하드웨어 크래시 시뮬레이터
int* ptr = nullptr; *ptr = 42; // <-- 0번 주소(가상 주소 0x0) 쓰기 시도
[CPU MMU] 가상 주소 0x00000000 변환 요청 [PTE 검사] Present = 0 (0번 페이지는 OS가 의도적으로 미할당 상태로 유지) [하드웨어 인터럽트] CPU Page Fault Exception 발생 (Vector #14) [OS 커널 개입] 보호되지 않은 미할당 메모리 접근 확인 ➔ 프로세스에 SIGSEGV 전달 [결과] Segmentation Fault (Core Dumped) ➔ 프로세스 강제 종료
