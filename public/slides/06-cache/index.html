01. 메모리 계층 구조와 속도 격차 (Memory Wall)

CPU 코어 연산 속도와 메인 메모리(DRAM) 접근 속도 사이의 거대한 지연시간 격차와 캐시의 필연성

MEMORY HIERARCHY PYRAMID
1. CPU 레지스터 < 0.5 ns (< 1 cyc) | ~1 KB
2. L1 캐시 (SRAM) ~1 ns (4 cyc) | 64 KB
3. L2 캐시 (SRAM) ~4 ns (14 cyc) | 1 MB
4. L3 캐시 (LLC SRAM) ~15 ns (50 cyc) | 32 MB
5. 메인 메모리 (DRAM) ~70 ns (200 cyc) | 32 GB
6. 보조기억장치 (NVMe SSD) ~10,000 ns (10,000+ cyc) | 1 TB
⏱️ CPU 지연시간(Latency) 시각적 비교
L1 캐시
4 cyc
메인 DRAM
200 cyc (200배 느림!)
🚧 폰 노이만 병목과 메모리 벽 (Memory Wall)
무어의 법칙으로 CPU 코어 연산 속도는 수십 년간 수천 배 빨라졌지만, 메인 메모리(DRAM)의 접근 지연시간은 고작 몇 배 개선되는 데 그쳤습니다. CPU가 DRAM에서 데이터를 직접 가져오려면 약 150~200 사이클 동안 아무 일도 못 하고 멈춰 서 있는(Pipeline Stall) 현상이 발생합니다.
⚡ SRAM 캐시의 구원: 계층적 완충망
DRAM보다 수십 배 빠르지만 비싸고 전력을 많이 소모하는 SRAM(Static RAM)을 코어 바로 옆에 L1, L2, L3 다단계로 배치했습니다. 자주 쓰는 데이터를 고속 캐시에 미리 올려둠으로써, CPU가 느린 DRAM 버스를 직접 두드리는 횟수를 극적으로 줄입니다.
📊 수치로 체감하는 인간 시간 환산
CPU 1 클럭(0.3ns)을 인간 시간 1초로 가정하면:
• L1 캐시: 4초 (책상 위 펼쳐진 노트)
• L3 캐시: 1분 (옆방 서랍장)
• 메인 메모리 DRAM: 4분 30초 (건물 밖 편의점 왕복)
• NVMe SSD: 수일 ~ 수개월 (우주선 타고 지구 반대편 왕복)

CPU가 단 4바이트 arr[0]을 요청하더라도, 하드웨어는 메모리 버스를 통해 64바이트 블록 전체(16개 int)를 통째로 L1 캐시 슬롯에 적재합니다.
주소 비트 분할: Tag (상위 비트) | Index (슬롯 선택) | Offset (0~63B)
⏱️ 시간적 지역성 (Temporal Locality)
"방금 접근한 메모리는 아주 가까운 미래에 다시 접근할 가능성이 극도로 높다."
• 대표 사례: 반복문 카운터 변수 i, 누적합 sum, 빈번히 호출되는 함수 코드 및 스택 프레임.
• 하드웨어 대처: 최근 접근한 데이터를 캐시 최상위에 유지(LRU 알고리즘)하여 다음 접근 시 1사이클에 적중(Hit)시킵니다.
📐 공간적 지역성 (Spatial Locality)
"어떤 메모리 주소에 접근했다면, 그 주변 주소들도 곧이어 접근할 가능성이 매우 높다."
• 대표 사례: 1차원 연속 배열 순차 순회, 연속된 구조체 멤버 필드 참조, 순차 인스트럭션 실행(PC = PC + 4).
• 하드웨어 대처: 캐시는 바이트 단위가 아닌 64B Cache Line 단위로 주변 데이터를 넉넉히 퍼옵니다.
📦 왜 64바이트인가?
메모리 버스를 열고 닫는 오버헤드 때문에 4바이트씩 찔끔찔끔 가져오는 것은 대역폭 낭비입니다. 현대 x86-64 및 ARM64(Apple Silicon 포함)는 64바이트를 하드웨어 표준 전송 블록 단위로 채택하고 있습니다.

03. 2차원 배열과 캐시 친화적 순회 패턴

행 우선(Row-Major) vs 열 우선(Column-Major) 메모리 배치에 따른 캐시 적중률과 극단적인 성능 격차

MEMORY LAYOUT & TRAVERSAL
✅ 행 우선 순회 (Row-Major Traversal: Cache-Friendly)
가로 방향 순차 전진: arr[0][0] → arr[0][1] → arr[0][2] → arr[0][3]
➔ 첫 1회 Miss로 64B(16개) 적재 후, 다음 15회 연속 Hit! (적중률 93.75%)
[MISS] ➔ [HIT] ➔ [HIT] ➔ [HIT] ➔ [HIT] ➔ [HIT] ...
❌ 열 우선 순회 (Column-Major Traversal: Cache-Unfriendly)
세로 방향 스트라이드 점프: arr[0][0] → arr[1][0] → arr[2][0] → arr[3][0]
➔ 매 스텝마다 64B 라인 경계를 벗어나 매번 Miss 발생! (적중률 0~10%)
[MISS] ➔ [MISS] ➔ [MISS] ➔ [MISS] ➔ [MISS] ...
🚀 행 우선 순회: 공간 지역성의 극대화
C/C++ 표준에서 2차원 배열은 메모리 상에 행(Row) 단위로 연속 배치됩니다. 루프의 안쪽 인덱스를 열(Column)로 두면, CPU는 메모리에 놓인 물리적 순서 그대로 순차 전진합니다. 하드웨어 프리페처(Hardware Prefetcher)가 다음 캐시 라인을 예측하여 미리 당겨오므로 병목이 전혀 없습니다.
💥 열 우선 순회: 공간 지역성 완전 파괴
루프의 안쪽 인덱스를 행(Row)으로 두면 다음 원소의 주소가 행 크기(Stride)만큼 크게 점프합니다. 앞서 캐시 라인으로 함께 퍼온 15개의 인접 데이터를 전혀 쓰지 않고 버린 뒤, 나중에 다시 돌아왔을 땐 이미 캐시에서 쫓겨나 매번 DRAM을 찔러야 합니다.
📊 실측 벤치마크: 알고리즘 복잡도의 함정
두 코드의 수학적 연산 횟수는 O(N × M)으로 100% 동일합니다. 그러나 대규모 배열에서 실제 실행 시간은 열 우선 순회가 10배~30배 이상 느립니다. 알고리즘의 점근적 표기법보다 하드웨어 캐시 라인을 고려한 설계가 실전 성능을 결정합니다.
