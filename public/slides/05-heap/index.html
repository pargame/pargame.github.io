01. 스택(Stack) vs 힙(Heap) 메모리 구조 비교

컴파일 타임에 크기가 확정되는 정적 스택과, 런타임에 동적으로 크기를 늘려 쓰는 힙의 구조적 차이

🔻 스택 영역 (Stack) - 아래로 성장 (↓) @8000 (Top of Memory)
자유 공간 (Free Gap) - 스택과 힙이 마주보며 메모리 공간 공유
🔺 힙 영역 (Heap) - 위로 성장 (↑) @3000 (동적 할당 풀)
데이터 영역 (BSS / Data) 전역·정적 변수
코드 영역 (Text/Code) @1000 (기계어 코드)
스택은 높은 주소(@8000)에서 아래로 자라고, 힙은 낮은 주소(@3000)에서 위로 자랍니다.
스택 메모리 (Stack Memory)
컴파일 시점에 변수 크기가 확정되며, 함수 호출과 반환에 따라 LIFO(Last-In, First-Out) 순서로 CPU 레지스터(SP)를 단순히 증감시켜 초고속으로 자동 할당 및 해제됩니다. 하지만 함수 스코프를 벗어나면 즉시 소멸하며, 크기 제한(수 MB)이 있습니다.
📦 힙 메모리 (Heap Memory)의 필요성
런타임에 사용자 입력이나 네트워크 패킷처럼 크기를 미리 알 수 없는 대용량 데이터를 처리할 때 사용합니다.
  • 생명주기 독립성: 함수가 반환되어도 명시적으로 해제할 때까지 데이터가 유지됨
  • 가변 크기: malloc, realloc을 통해 런타임에 크기 조정 가능
  • 포인터 간접 참조: 스택에 힙 블록의 시작 주소를 담아 참조
📈 주소 성장 방향과 충돌 방지
스택과 힙이 서로 마주보며 자라나도록 배치하여, 프로세스는 사전 영역 분할 없이 중앙의 미할당 자유 공간을 유연하게 공유합니다.

02. 동적 할당의 생애주기와 포인터 매핑

malloc으로 힙 공간을 할당받아 주소를 포인터 변수에 담고, free로 반납하는 라이프사이클

스택 프레임 (Stack @8000)
포인터 변수 ptr
값: @3040
➔ ➔
힙 영역 (Heap @3000)
할당 블록 (@3040)
16 Bytes (데이터)
동적 할당 4단계 라이프사이클
1. malloc(16) 요청 2. 주소(@3040) 반환 3. *ptr 역참조 사용 4. free(ptr) 반납
힙 관리자 (Memory Allocator)의 역할
malloc 호출 시 매번 커널 시스템 콜(brk, mmap)을 호출하면 심각한 성능 저하가 발생합니다. C 런타임의 힙 관리자(ptmalloc, jemalloc 등)는 미리 커널로부터 넉넉한 힙 풀을 받아두고, 유저 요청 크기에 맞는 블록을 잘라 시작 주소를 반환합니다.
⚡ free()와 프리 리스트(Free List)
사용이 끝난 메모리는 free(ptr)를 통해 힙 관리자의 **프리 리스트(Free List)**로 반납됩니다. 반납된 블록은 즉시 운영체제에 반환되는 것이 아니라, 향후 다른 `malloc` 요청 시 재사용될 수 있도록 관리자가 보관합니다.
⚠️ 자원 반납의 명시적 의무
스택과 달리 힙 메모리는 함수가 종료되어도 자동으로 해제되지 않습니다. 프로그래머가 free()를 명시적으로 호출하기 전까지 영구적으로 메모리를 점유합니다.

03. 메모리 누수와 단편화의 하드웨어 원리

free를 잊어 주소를 잃어버리는 메모리 누수와, 쪼개진 빈 공간 때문에 할당이 실패하는 단편화

1. 메모리 누수 (Memory Leak)
포인터 변수 ptr이 사라져 주소를 영구 분실 ➔ 힙 블록이 해제되지 못하고 고립 점유
2. 외부 단편화 (External Fragmentation)
빈 공간 64B
점유 64B
빈 공간 64B
총 빈 공간은 128B이나, 연속 100B 블록 요청 시 적재 불가 (OOM 발생!)
메모리 누수 (Memory Leak)의 위험성
malloc한 힙 블록의 주소를 덮어쓰거나 포인터 변수가 스코프를 벗어나면, 프로그램은 해당 메모리를 해제할 방법이 영원히 사라집니다. 장시간 실행되는 서버 프로그램에서 누수가 누적되면 힙이 고갈되어 OS 커널의 OOM Killer(Out Of Memory)에 의해 프로세스가 강제 종료됩니다.
🧩 외부 단편화 (External Fragmentation)
블록들이 임의의 순서로 할당되고 해제되면서 힙 메모리 사이에 자잘한 빈 구멍들이 생기는 현상입니다. 메모리 총 여유 공간의 합은 충분하더라도, 연속된 물리 가상 주소 공간이 부족하면 새로운 할당 요청이 실패합니다.
🛡️ 모던 할당자의 단편화 방어 기법
인접한 빈 블록을 하나로 묶는 **병합(Coalescing)**과, 동일한 고정 크기 블록들을 미리 풀로 구성해 재사용하는 **슬랩 할당자(Slab Allocator)**를 통해 외부 단편화를 최소화합니다.
